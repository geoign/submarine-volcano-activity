# Agent instructions for submarine-volcano-activity

This repository is the public database of a satellite monitoring system for shallow submarine
volcanoes, and the static site that shows it (GitHub Pages:
<https://geoign.github.io/submarine-volcano-activity/>). The monitoring system itself lives in
another, private checkout and is not published. Its location, the working folder and the rclone
destination of the image store are in `local.toml` (not committed; the README shows its form).
`CLAUDE.md` is a copy of this file.

## Layout

| Path | Content |
|---|---|
| `db/` | The published tables. Generated by `tools/build_db.py`; never edit by hand |
| `curation/` | Hand-made inputs of the build: `overrides.csv` (class of single episodes), `volcano_summaries.csv`, `notes_en.csv` (translations of review notes), `names_ja.csv`, `figures.csv`, `human_review.csv` (the author's reviews), `jcg_sites.csv`, `jcg_categories.csv` and `jcg_observations.csv` (observations of the Japan Coast Guard's database), `hindcast2_triaged_days.csv` (the alert days of the second hindcast's episodes as they were triaged on 2026-11-14: a review counts for those days; frozen, never made again from the store) |
| `index.html`, `volcano.html`, `episodes.html`, `assets/` | The site. Plain HTML, CSS and ES modules, no build step, no CDN |
| `about.html` | Generated by `tools/build_about.py` from `docs/METHODS.en.md` and `docs/METHODS.ja.md` |
| `docs/` | Methods (both languages), data dictionary |
| `tools/`, `tests/` | Build, checks, tests (`python -m pytest tests`) |

Satellite images are not in the repository. They are in the owner's Cloudflare R2 bucket and
served at `https://gis.ikgm.net/submvolc/` (`ql/<zone>/<pass>.jpg`, `wide/`, `fig/`). The working
folder is synchronised to a cloud drive: keep it to text and the few images of the interface.

## Updating the database

1. `python tools/build_db.py` reads the monitor's stores (read only) and rewrites `db/`.
2. `python tools/check_db.py` must end with `OK`; `python tools/check_images.py 20` asks the image store.
3. `python tools/sync_images.py --since <day of the last update>` sends the new quicklooks.
4. `python tools/notes.py pending` lists review notes without an English text; translate them and
   `python tools/notes.py merge <file>`, then build again.
5. `python tools/build_review.py` rebuilds the author's review form (`review/index.html`, opened
   from disk, not committed). The author saves the reviews from the form into
   `curation/human_review.csv`; the next build gives those episodes the status `human-reviewed`.
   Never edit that file by hand or on the author's behalf: it records what a person looked at.
   A row whose episode has gone from the tables stays; `tools/check_db.py` notes it. The form
   lists an episode again when passes were added to it after the day of its review.
   When the author saved the file somewhere else and asks for it to be taken in, it replaces
   `curation/human_review.csv` as a whole, byte for byte, after a comparison: a row of the old
   file that the new one lacks is a review the author withdrew, or a file from another browser,
   so ask before it is lost. After new reviews, the summaries of `curation/volcano_summaries.csv`
   that the verdicts contradict are rewritten, and the author's comments get an English text
   (step 4). When the author asks for a review to be withdrawn, add a row to
   `curation/review_withdrawn.csv` (episode, time, reason) and leave the review file alone: the
   build and the form then ignore every copy of that review that is not newer.
6. Volcanoes of Japan: the Japan Coast Guard adds observations to its database of submarine
   volcanoes a few times a year. `python tools/parse_jcg.py --fetch` reads its pages again (one
   request at a time) and extracts the records; `python tools/import_jcg.py --pending <file>`
   lists the new texts that report activity. Summarise them in English, then
   `python tools/import_jcg.py --retrieved <day>` and build again.
7. Commit. Push only when the owner asks, or under a standing instruction for the routine update.

## Rules

- Never write to the monitoring system's folder from here. Everything this repository needs from
  it is read by `tools/build_db.py`.
- The class of an episode is not the reviewer's "interest". Interest says how much an episode
  deserved a second look; the class follows the conclusions of the review reports and the owner's
  verdicts. A change of class for a single episode goes into `curation/overrides.csv` with its
  reason, not into the code.
- Do not write "unreported" or "first report" anywhere. `prior_reports` says what was read and
  when; an empty cell means nothing was checked. The Smithsonian's weekly reports and Bulletin for
  a volcano must be read before anything is said about earlier reports; for a volcano of Japan
  also its page in the Japan Coast Guard's database (`db/jcg_observations.csv`).
- The Coast Guard's observations are another body's record. Its Japanese text is shown as the
  source gives it, and the source and the fact of editing are named wherever the records appear;
  the category, the phenomena and the English summary are ours. An observation never changes a
  class by itself: an episode it disagrees with goes up in the author's review form.
- Text for the public is in English and Japanese. Japanese text longer than a page goes through
  the owner's writing check before it is committed.
- Nothing private goes into a commit: no local user paths, no keys, no e-mail address other than
  the author's public one. `tools/check_db.py` scans for these; run it before every commit.
- The colours of the classes were validated for colour-vision deficiency (three steps of one warm
  hue for the volcanic classes, one hue each for recurrent and airborne, greys for the rest).
  Do not add a hue without running a palette check; identity is always also carried by a label.
- Image URLs are derived from zone, time and satellite. Do not rename objects in the image store;
  a quicklook that was redrawn keeps its key.

## Things that already went wrong once

- A page of the Coast Guard's database is not one volcano. The page of Fukutoku-Oka-no-Ba also
  has Minami-Ioto, and Kita-Fukutoku-tai has a page of its own but is a zone of the same volcano
  here. The first comparison took every row of a volcano for every episode. An observation now
  counts for the zones its feature lies in (`curation/jcg_sites.csv`), and for the low-resolution
  episodes of the volcano. The table of Kaitoku Seamount is of Higashi-Kaitoku-ba only. Sofu-gan
  (孀婦岩) and the Sofu Seamount caldera, 20 km to its west, are different volcanoes (the author,
  2026-11-14): Sofu-gan is not a target here, and its table is not attached to the caldera.
- The first rules read "湧出" (discoloured water welling up) as bubbles: 17 rows said "bubbles"
  under the Coast Guard's name without the source saying so. A label is added only for a word the
  text has; `prior_reports` says "reported", not "activity", and says how far the records reach
  where there is none, because a table can begin late (Omuro-dashi: 2025).
- The review form once wrote its file without reading it: opened in another browser, it would
  have replaced the saved reviews with its own. It now merges the file and the browser's storage
  before every write, and a withdrawn review stays as an entry without a verdict.
- `num()` of the build once stripped trailing zeros from whole numbers, so a bearing of 290 was
  written 29 and ten hot pixels became one. Zeros are stripped from a fraction only; the test
  covers multiples of ten.
- A review carried over from an overlapping episode is not a review of this episode. The second
  hindcast took the verdict of the first for every episode within 21 days of one reviewed there,
  and the monitor's list inherits the triage of 2026-11-12 the same way. The build compares the
  alert days: none in common means `unreviewed`, some means basis `ai_review_partial`. Do not
  write that every alert was reviewed.
- The survey's low-resolution field `days_seen` counts alert days, and its kind `bright` answers
  to cloud. The build counts the visible days of an episode from the daily record and lists
  discoloured water only.
- DOM `append(null)` prints the word "null". Use `add()` or `el()` of `assets/js/common.js`,
  which leave out null and false.
- The monitor reads a catalogue eruption without an end date as "ongoing". For an eruption that
  began years earlier that is no match (McDonald Islands, eruption of 2001); the build drops such
  matches for low-resolution episodes, and `known_periods.csv` has `continuing` from the
  catalogue's own flag or a `>` before the end year (Kavachi from 2020: '>' 2024-04-24, the last date
  the catalogue gives for it; shown as "..continuing", not as an end).
- "persistent" in the monitor's zone table is how thresholds are set, not the owner's list of
  places with a usual feature. Fukutoku-Oka-no-Ba is "persistent" there for frequent volcanic
  discoloured water; the rule that turns flagged episodes into `recurrent` uses the owner's list
  ("常時" in the source table) only.
